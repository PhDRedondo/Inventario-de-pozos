1. Propósito y alcance

Esta guía describe el estado desplegable de la herramienta Validación Inventario de Pozos (VIP), los pasos para mantener el piloto en Vercel y los requisitos de plataforma que OTI debe habilitar para producción institucional.

Alcance del piloto: demo funcional, revisiones técnicas y mesa OTI. Fuera de alcance del piloto solo: continuidad de datos, IdP institucional, backups y cumplimiento formal de privacidad. Esos puntos son prerequisitos de producción (véase §7).

4. Operación del piloto en Vercel

  1. Proyecto: inventario-pozos-anh (asociado al repo GitHub PhDRedondo/Inventario-de-pozos, rama main).
  2. Framework: Next.js (detección automática).
  3. Configurar variables de entorno (§5) en Production (y Preview si aplica).
  4. Redeploy tras cambiar secretos.
  5. Verificar: /login responde; rutas API sin sesión retornan 401; HTTPS activo.
  6. Tras redeploy o cold start agresivo, la DB en /tmp puede reiniciarse: el admin semilla se recrea con ANH_ADMIN_PASSWORD.
Implicación: el piloto no garantiza retención de datos entre reinicios de instancia. No usar Vercel+/tmp como producción de inventario oficial.

6. Checklist antes de considerar producción

Ya cubierto por la aplicación (piloto)

  • Secretos por entorno; sin credenciales embebidas de producción.
  • Sesión firmada + idle/absoluto; middleware con verificación HMAC.
  • Headers de seguridad; CSRF básico por Origin + SameSite.
  • Autorización por rol y scope; auditoría; validación de uploads.
  • CI básica en GitHub Actions.

Obligatorio antes de producción (OTI / plataforma)

  • Base de datos persistente (PostgreSQL o equivalente ANH) fuera de /tmp.
  • Backups automatizados, retención y prueba de restauración.
  • Active Directory / SSO + MFA; apagar login local y demo.
  • Cifrado en reposo / KMS según política ANH.
  • WAF / rate limit perimetral; monitoreo y alertas.
  • Textos y flujos Ley 1581; matriz de datos; canal ARCO.
  • Ambientes (dev/test/prod), UAT firmada, expediente MA-02, runbook de incidentes.

8. Operación cotidiana del piloto

  • Altas de usuario: rol admin → Usuarios.
  • Carga operadora: Cuaderno → Excel → validación → envío.
  • Consulta ANH: Panel consolidado + Analítica / PDF.
  • Auditoría: panel admin de audit_log.
  • Rotación de secretos: actualizar env en Vercel → redeploy → re-login de usuarios.
