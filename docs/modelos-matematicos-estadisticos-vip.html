1. Alcance y naturaleza de los modelos

Los modelos de VIP son deterministas y paramétricos: se expresan como funciones matemáticas / agregaciones estadísticas con parámetros calibrables (umbrales, catálogos, severidades). No hay estimadores bayesianos ni modelos de aprendizaje automático entrenados en producción; la estadística es principalmente descriptiva y comparativa.

2. Modelo de clasificación de calidad por pozo

2.1 Formulación

Sea un pozo \(i\) con conjunto de hallazgos \(H_i\). Cada hallazgo \(h\) tiene severidad \(s(h) \in \{\mathrm{error},\mathrm{warning},\mathrm{info}\}\).

Conteo de severidades Eᵢ = |{ h ∈ Hᵢ : s(h) = error }|
Wᵢ = |{ h ∈ Hᵢ : s(h) = warning }|
Estado de validación del pozo estado(i) =
   invalid   si Eᵢ ≥ 1
   warning  si Eᵢ = 0 ∧ Wᵢ ≥ 1
   valid     si Eᵢ = 0 ∧ Wᵢ = 0

Equivalente booleano usado en código: is_valid ⇔ Eᵢ = 0.

2.2 Agregados de lote (cuaderno / carga)

Para un conjunto de resultados \(R = \{r_1,\ldots,r_n\}\):

Resumen de lote — summarizeValidation() valid        = |{ r : is_valid ∧ warning_count = 0 }|
with_warnings = |{ r : is_valid ∧ warning_count ≥ 1 }|
invalid      = |{ r : ¬is_valid }|
error_total   = Σ Eᵢ
warning_total = Σ Wᵢ
Puerta de envío: el cuaderno solo puede enviarse a la ANH si invalid_records = 0 (ningún pozo en estado invalid). Los warning no bloquean el envío.

2.3 Implementación

  • src/lib/validation.ts → validateWell(), summarizeValidation()
  • ~59 chequeos activos (obligatorios, catálogo, DANE, condicionales, numéricos, coordenadas, UWI).
  • Cada hallazgo aporta tupla (field, severity, message, rule).

2.4 Ajuste

  • Cambiar severidad de una regla (error↔warning) altera la tasa de bloqueo.
  • Ampliar/restringir catálogos maestros cambia la función indicador de pertenencia.
  • Condicionales AVM y levantamiento son reglas lógicas parametrizadas por valor de atributos.

3. Modelos de agregación estadística (Analítica ANH)

Las métricas se agrupan en cuatro temas \(T \in \{\mathrm{producción},\mathrm{inyección},\mathrm{operativo},\mathrm{portafolio}\}\). Para una población filtrada \(S\) (línea base nacional o entidad de comparación):

3.1 Promedios de variables continuas

Producción e inyección usan media aritmética sobre valores parseables:

Media — ejemplo petróleo acumulado μ̂(prod_petroleo) = (1 / |S*|) · Σ_{j ∈ S*} x_j
donde S* = { pozos en S con x parseable como REAL; se excluyen vacíos vía NULLIF }

Métricas: prod_dias, prod_petroleo, prod_agua, prod_gas, iny_dias, iny_agua, iny_gas, iny_otros.

3.2 Proporciones (perfil operativo)

Proporción / porcentaje p̂(A) = 100 · |{ j ∈ S : j satisface A }| / |S|
MétricaPredicado A
pct_activoestado_pozo = 'Activo'
pct_horizontalángulo contiene H / horizontal
pct_productorobjetivo contiene P / Productor
pct_inyectorobjetivo contiene I / Inyector
pct_coordslatitud y longitud no vacías
pct_uwiUWI fiscalizado no vacío

3.3 Ratios de portafolio

Densidad y diversidad wells_per_op = |S| / |{operadoras distintas en S}|
dept_span     = |{departamentos distintos}|
muni_span     = |{municipios distintos}|
avg_contracts = |{contratos distintos}| / |{operadoras distintas}|

3.4 Implementación

  • Definición de métricas: ANALYTICS_THEMES en src/lib/analytics.ts (aggregateSql).
  • Ejecución: src/lib/analytics-db.ts ensambla SELECT AVG(...) AS key, ....
  • API: GET /api/analytics.

4. Modelo de índice comparativo (radar, base 100)

4.1 Formulación

Sea \(b_k\) el valor crudo de la métrica \(k\) en la línea base nacional y \(c_k\) el valor crudo de la entidad comparada.

Normalización a índice 100 — buildRadarComparison() baseline_k := 100

comparison_k :=
  (c_k / b_k)·100    si b_k > 0
  120                si b_k = 0 ∧ c_k > 0
  0                  si b_k = 0 ∧ c_k = 0
Delta porcentual Δ_k (%) = ((c_k − b_k) / b_k)·100  si b_k > 0
Δ_k (%) = 0                         si b_k = 0

Redondeo de presentación: índice y delta a 1 decimal; crudos a 2 decimales.

Interpretación: un valor de radar 100 = igual a la media/agregado nacional de esa métrica. 80 = 20% por debajo; 130 = 30% por encima. El caso especial 120 cuando la base es 0 evita división por cero y marca presencia relativa cuando la nación no reporta magnitud.

4.2 Implementación

  • buildRadarComparison() en src/lib/analytics.ts
  • Visualización Recharts en src/app/analitica/page.tsx
  • Exportación en src/lib/analytics-report-pdf.ts

4.3 Ajuste

  • Cambiar la población base (filtros del inventario validado) redefine \(b_k\).
  • Sustituir media por mediana / winsorización requeriría modificar aggregateSql.
  • El valor 120 del caso \(b_k=0\) es un parámetro de diseño ajustable.

5. Modelo de heatmap (ratio vs nacional)

5.1 Formulación

Para una celda (p. ej. departamento × métrica o entidad × métrica):

Ratio porcentual ρ = (valor_celda / valor_base)·100  si valor_base > 0
ρ = 0                            en caso contrario

5.2 Escala de color (función escalón)

heatColor(ρ) — umbrales ρ ≥ 130 → rojo    #e8381a  (muy por encima)
ρ ≥ 110 → naranja #ff8c00
ρ ≥ 90  → amarillo #ffe600 (cerca de la base)
ρ ≥ 70  → celeste  #38bdf8
ρ < 70  → (rango inferior de la escala UI)

≥130%   ≥110%   ≥90%   ≥70%

5.3 Implementación y ajuste

  • Función heatColor() en src/app/analitica/page.tsx.
  • Ajuste institucional: mover los umbrales {70, 90, 110, 130} redefine qué se considera “normal” vs “desviado”.
  • Top-N de filas (p. ej. 8 deptos / 6 operadoras) es un parámetro de presentación, no del ratio.

6. Modelo de flujo Sankey (conteos multivariados)

6.1 Formulación

Se construyen dos capas de enlaces a partir de conteos en el subconjunto filtrado del panel:

Pesos de enlace w(depto → estado)     = |{ pozos : depto=d ∧ estado=e }|
w(estado → operadora) = |{ pozos : estado=e ∧ operadora=o }|
   o bien
w(estado → validación)= |{ pozos : estado=e ∧ estado_validación=v }|

El grosor visual del enlace es proporcional a \(w\). Los nodos se indexan por clave columna::valor; la conservación de flujo es por construcción de conteos (no es un modelo de balance energético).

6.2 Implementación

  • Agregación SQL: getSankeyFlowData() en src/lib/db.ts vía /api/stats.
  • Grafo UI: buildSankeyChartData() en src/lib/sankey-data.ts + WellsSankeyChart.tsx.
  • Layout Recharts Sankey con iterations=64 (parámetro numérico del algoritmo de posicionamiento, no del modelo de datos).

6.3 Rankings del panel

Ranking por frecuencia top_k(dimensión) = arg max_{parcial} COUNT(*) ordenado DESC, limitado a k

Se aplica a operadoras y departamentos en el subconjunto filtrado actual.

7. Modelos auxiliares: geografía y UWI

7.1 Normalización geográfica (matching)

Función de canonicidad: se aplica reparación de encoding y normalización Unicode NFD, eliminación de diacríticos y colapso de espacios → clave de búsqueda en mapas DANE.

Igualdad geográfica deptNamesMatch(a,b) ⇔ normalizeGeoName(a) = normalizeGeoName(b)

Implementación: src/lib/geo.ts, src/lib/etl.ts. Es un modelo de equivalencia, no probabilístico.

7.2 Validación de coordenadas

Dominio geodésico latitud ∈ [−90, 90],   longitud ∈ [−180, 180]
coordenadas proyectadas: parsability numérica (X/Y Bogotá y nacional)

7.3 Ensamble UWI fiscalizado

Modelo de composición de cadena (no estadístico) según instructivo:

Estructura UWI = Depto(2) ‖ Muni(3) ‖ Sigla(4+) ‖ Número(4) ‖ Clúster ‖ Ángulo ‖ Trayectoria ‖ Objetivo ‖ "-" ‖ Terminación

Funciones de extracción (sigla, número, clúster) son heurísticas deterministas sobre texto normalizado. La validación del instructivo agrega hallazgos al modelo de calidad (§2). Implementación: src/lib/uwi.ts.

9. Síntesis

VIP implementa una pila cuantitativa explícita:

  1. Clasificador de calidad por conteo de errores/warnings.
  2. Estimadores descriptivos (medias, proporciones, ratios de diversidad).
  3. Índice relativo base-100 para benchmarking entidad vs nación.
  4. Ratios coloreados por umbrales (heatmap).
  5. Flujos de conteo (Sankey) y rankings por frecuencia.
  6. Funciones de equivalencia y composición (geo, UWI) que alimentan los modelos anteriores.

Formulación, implementación y ajuste están acoplados de forma deliberada: las matemáticas son legibles, el código las refleja 1:1, y los umbrales/catálogos son los tornillos de calibración institucional.
